# 대시보드 캘린더 설계

작성일: 2026-09-18

## 배경

페이지를 언제 만들었고 언제 보냈는지, 고객이 언제 신청했고 누구의 체험이 언제 끝나는지가
지금은 각각 다른 화면에 흩어져 있다. 한 달 치를 한 판에 보고 싶다.

## 결정

- 대시보드(`/admin`) **최상단**에 월 단위 달력 격자를 둔다. "달력처럼 한 판에"라는
  요구에 월 격자가 가장 가깝다.
- 격자 칸은 좁으므로 칸에는 **아이콘과 건수만** 넣고, 날짜를 클릭하면 격자 아래에
  그날 이벤트 상세가 펼쳐진다.
- **새 테이블·컬럼을 만들지 않는다.** 이미 있는 `pages`와 `customers`의 날짜를 읽어 조합한다.
- 발행일(`published_at`)은 캘린더에 넣지 않는다 — 생성·전송과 날짜가 거의 겹쳐
  칸만 복잡해진다. 필요해지면 나중에 추가한다.

## 1. 이벤트

| 아이콘 | 종류 | 출처 | 제목 | 이동 |
|---|---|---|---|---|
| ✏️ | `page-created` | `pages.created_at` (KST 날짜로 변환) | 페이지 제목 | `/admin/{id}/edit` |
| 📤 | `page-sent` | `pages.sent_on` | 페이지 제목 + 태그 | `/admin/published` |
| 📥 | `customer-applied` | `customers.submitted_at` (KST 날짜로 변환) | 이름 · 사무실 | `/admin/customers/{id}` |
| ⚠️ | `trial-ending` | `customers.trial_started_on + 30일` | 이름 · 사무실 | `/admin/customers/{id}` |

`trial-ending`은 `status`와 무관하게 `trial_started_on`이 있으면 만든다 — 이미 전환/이탈한
고객도 "그때 체험이 끝났다"는 기록으로 달력에 남는 편이 낫다.

타임스탬프(`created_at`, `submitted_at`)는 `Asia/Seoul` 기준 날짜로 변환한다. UTC 자정
전후에 하루가 밀리는 것을 막기 위해서다. `sent_on`, `trial_started_on`은 이미 날짜 문자열이다.

## 2. 화면

```
┌─ 2026년 9월 ─────────────────── [<] [오늘] [>] ─┐
│  일    월    화    수    목    금    토           │
│                    1     2     3     4     5    │
│                         ✏️2                      │
│   6     7     8     9    10    11    12         │
│                   ✏️1 📤1                        │
│  13    14    15    16   [17]   18    19         │
│              📥1        📤1 ⚠️1                   │
└─────────────────────────────────────────────────┘

▸ 9월 18일
  📤 전송  추석선물, 이렇게 안 챙기면…  [세무사 1차]
  ⚠️ 체험 종료  박회계 · B사무소
```

- 기본은 이번 달. 오늘 날짜 칸에 테두리 강조.
- `[<] [>]`로 월 이동, `[오늘]`로 이번 달 복귀. 상태는 URL 쿼리 `?month=YYYY-MM`으로
  유지해 새로고침·공유해도 같은 달이 열린다.
- 격자는 일요일 시작 7열. 달의 앞뒤 빈 칸은 회색으로 비워 둔다(이전/다음 달 날짜를
  넣지 않는다 — 클릭 대상이 늘어 헷갈린다).
- 각 칸: 날짜 숫자 + 그날 이벤트의 아이콘. 같은 종류가 2건 이상이면 아이콘 옆에 숫자.
  이벤트가 없는 날은 숫자만.
- 날짜 클릭 → 격자 아래에 그날 이벤트 목록이 펼쳐진다. 같은 날짜를 다시 누르면 접힌다.
- 최초 진입 시 **오늘**이 선택되어 있다(이번 달을 보고 있을 때만). 다른 달로 이동하면
  선택이 풀린다.
- 이벤트 항목을 클릭하면 위 표의 경로로 이동한다.

## 3. 구현

| 파일 | 역할 |
|---|---|
| `lib/calendar/events.ts` | 순수 함수: `toCalendarEvents`, `buildMonthGrid`, `groupByDate`, `parseMonth`, `shiftMonth` |
| `lib/calendar/events.test.ts` | 위 함수 테스트 |
| `components/dashboard/Calendar.tsx` | 격자 + 월 이동 + 날짜 선택 (client) |
| `components/dashboard/CalendarDayDetail.tsx` | 선택된 날의 이벤트 목록 |
| `app/admin/page.tsx` | `listPages`와 `listCustomers`를 함께 조회해 캘린더에 넘김 |

`/admin`이 고객 목록까지 조회하게 되지만, 페이지·고객 모두 수백 건 이하라 한 번에 읽는
편이 단순하다. 이벤트 변환은 서버에서 끝내고 `CalendarEvent[]`만 클라이언트로 내린다 —
클라이언트가 원본 레코드 전체를 들고 있을 이유가 없다.

"오늘"은 서버에서 `todayInSeoul()`로 계산해 prop으로 내린다. 클라이언트에서 계산하면
사용자 시스템 시계에 따라 달라진다.

## 에러 처리

- 잘못된 `?month=` 값(형식 오류, 존재하지 않는 달)은 이번 달로 대체한다.
- 이벤트가 하나도 없는 달은 빈 격자를 그대로 보여준다(별도 안내 문구 없음 — 격자 자체가
  "이 달엔 아무것도 없다"를 이미 말해 준다).
- 선택한 날짜에 이벤트가 없으면 상세 영역에 "이 날은 기록이 없어요."를 표시한다.

## 테스트

`lib/calendar/events.test.ts`:
- `buildMonthGrid`: 2026-09(9/1 화요일) 앞 빈칸 2개, 총 칸 수가 7의 배수, 마지막 날 30일
- 월 경계: 2026-02(윤년 아님, 28일), 2026-03
- `parseMonth`: `"2026-09"` 통과, `"2026-13"`·`"abc"`·`undefined`는 기본값(이번 달)
- `shiftMonth`: `"2026-12"` +1 → `"2027-01"`, `"2026-01"` -1 → `"2025-12"`
- `toCalendarEvents`: 4종 이벤트 생성, KST 변환(UTC 15:30 → 다음날), `sent_on`/`trial_started_on`이
  null이면 해당 이벤트 없음, 체험 종료 = 시작 + 30일
- `groupByDate`: 같은 날 여러 이벤트가 한 키로 묶이고 종류별 순서가 유지됨

UI는 dev 서버에서 수동 확인한다.
