# 카카오 브랜드메시지 랜딩페이지 생성기 설계

## 배경 및 목표

너겟(nugget)은 세무사(잠재 고객)에게 카카오톡 브랜드메시지로 콘텐츠 소식을 보내 신규 고객을 유치한다. 메시지에는 카카오톡 자체 네이티브 버튼("바로 확인하기" 등)이 있고, 클릭 시 해당 콘텐츠를 자세히 보여주는 랜딩페이지로 연결된다.

현재 이 랜딩페이지는 Framer로 건마다 수작업 제작하고 있어(참고: 노션 "페이지 생성기" 문서) 번거롭다. 이 프로젝트는 그 수작업을 대체하는 내부 도구를 만든다: 콘텐츠를 폼에 입력하면 고유 URL을 가진 랜딩페이지가 자동 생성되고, 그 URL을 카카오 브랜드메시지 발송 도구(별도 외부 툴)의 버튼 링크로 붙여넣어 쓴다.

**참고 자료**:
- 노션 "페이지 생성기" 문서 — 타이포그래피/레이아웃 디자인 가이드, 실제 콘텐츠 페이지 스크린샷 예시
- 카카오톡 브랜드메시지 발송 화면 스크린샷 — 너겟 채널명 + 이미지 + 제목 텍스트 + 네이티브 버튼("바로 확인하기") 구조. 이 버튼은 카카오 비즈니스 메시지 도구에서 관리되며 이 프로젝트의 스코프 밖이다.
- `../nugget-tax` — 같은 조직의 자매 프로젝트(너겟 서비스 자체를 세무사에게 소개하는 별도의 정적 마케팅 랜딩페이지). 스택 컨벤션을 참고하되 완전히 독립된 프로젝트로 만든다.

## 아키텍처

- **Next.js 15 (App Router) + TypeScript + Tailwind CSS**, `tax auto` 폴더에 새 프로젝트로 생성 (nugget-tax와 별도 저장소).
- **Supabase**: Postgres(콘텐츠 데이터) + Storage(배너 이미지 파일) 사용.
- 라우트:
  - `/admin` — 비밀번호 로그인 + 생성된 페이지 대시보드(목록)
  - `/admin/new`, `/admin/[id]/edit` — 블록 조립식 에디터
  - `/c/[slug]` — 공개 랜딩페이지 (카카오 버튼이 연결되는 실제 URL)
- Git: 로컬 저장소 초기화. 원격 저장소 연결/push는 사용자 확인 후 진행한다.
- 배포: Vercel을 전제로 하되, 실제 프로젝트 연결/배포는 이번 스코프에 포함하지 않는다.

## 데이터 모델

`pages` 테이블 (Supabase Postgres):

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | uuid (PK) | |
| `slug` | text (unique) | 기본값은 짧은 랜덤 문자열 자동 생성(한글 제목의 슬러그화가 어려워 랜덤 생성 후 사용자가 원하면 직접 영문으로 수정) |
| `title` | text | 관리용 제목, 페이지 `<title>`/메타에도 사용 |
| `status` | text | `draft` \| `published` \| `archived` |
| `blocks` | jsonb | 아래 블록 스키마의 배열, 순서가 곧 렌더링 순서 |
| `cta_label` | text | 페이지 최하단 자체 CTA 버튼 텍스트 (예: "상담 신청하기") |
| `cta_href` | text | CTA 링크 (URL 또는 `tel:...`) |
| `cta_color` | text | CTA 버튼 배경색 hex, 기본값 `#FEE500`(카카오 노랑) |
| `created_at` | timestamptz | |
| `updated_at` | timestamptz | |

`blocks` jsonb 배열의 요소 타입 3종:

```ts
type Block =
  | { type: "banner"; imageUrl: string; title?: string; subtitle?: string }
  | { type: "text"; heading?: string; bodyHtml: string } // bodyHtml은 Tiptap 출력, 서버에서 sanitize 후 저장
  | { type: "stats"; items: { number: string; label: string }[] } // items 2~4개
```

Supabase Storage 버킷 `banner-images`(public read)에 배너 이미지 파일을 업로드하고 public URL을 `imageUrl`에 저장한다.

## 에디터 UX (`/admin/new`, `/admin/[id]/edit`)

- 공통 필드: 제목(제목 변경 시 slug는 유지, 최초 생성 시에만 자동 생성), CTA 텍스트, CTA 링크, CTA 색상(색상 피커, 기본값 `#FEE500`)
- 본문은 "+ 블록 추가" 버튼으로 배너/텍스트/숫자카드 블록을 자유 순서로 추가. 각 블록에 위/아래 이동 버튼과 삭제 버튼(드래그 앤 드롭 없음).
  - **배너**: 파일 선택 시 즉시 Supabase Storage 업로드 + 썸네일 미리보기, 제목/부제 일반 텍스트 입력
  - **텍스트**: 소제목 일반 텍스트 입력 + 본문은 Tiptap 리치 에디터(툴바: 굵게/기울임/글자크기/강조색). 배너 제목·부제·숫자카드 라벨 등 다른 필드는 서식 편집 없이 일반 텍스트로 유지한다.
  - **숫자카드**: 카드 2~4개, 카드마다 숫자+라벨 일반 텍스트 입력, 카드 추가/삭제
- 저장 버튼 2개: "임시저장"(status=draft로 upsert) / "발행"(status=published로 upsert)
- 미리보기: 별도 프리뷰 화면을 만들지 않고 `/c/[slug]`를 그대로 사용한다. 관리자 쿠키가 있으면 draft/archived 상태에서도 "미리보기 모드" 배너와 함께 실제 렌더링을 볼 수 있다.

## 대시보드 (`/admin`)

- 전체 페이지를 `updated_at` 내림차순으로 목록 표시.
- 각 행: 상태 배지(임시저장/발행/보관) + 제목 + 생성일 + 수정일 + [URL 복사] [수정] [발행하기 또는 보관하기 — 상태에 따라 다른 액션 노출]
- "보관"은 소프트 삭제 개념으로, 완전 삭제 기능은 이번 스코프에 없음. 보관된 페이지는 다시 발행하거나 임시저장으로 되돌릴 수 있다.
- "새 페이지 만들기" 버튼으로 `/admin/new` 진입.

## 공개 랜딩페이지 비주얼 디자인 (`/c/[slug]`)

노션 "페이지 생성기" 문서의 디자인 가이드를 따른다:

- **타이포그래피**: 제목류(배너 제목, 텍스트블록 소제목)는 Noto Serif KR, 본문은 Noto Sans KR. `next/font/google`로 로드.
- **레이아웃**: 배너 이미지는 풀블리드, 텍스트·숫자카드 블록은 좁은 중앙 컬럼에 배치해 가독성 확보. 색상 사용을 최소화하고 옅은 회색 구분선과 여백만으로 정보 위계를 표현한다(과한 색 없이 선과 여백으로 위계를 잡는다는 원문 가이드 반영).
- **블록 렌더링**:
  - 배너: 이미지 아래에 제목(세리프)·부제(산세리프) 텍스트 배치(이미지 위 오버레이 대신 — 항상 가독성/대비 확보)
  - 텍스트: 소제목(세리프) + Tiptap에서 저장된 서식 그대로 렌더링되는 본문(산세리프)
  - 숫자카드: 2~4개 카드를 얇은 회색 선으로만 구분, 숫자는 세리프 굵게 크게, 라벨은 산세리프 작게
- **CTA 버튼**: 페이지 최하단 고정 배치, 에디터에서 지정한 `cta_color` 배경 적용, 텍스트 색은 배경 밝기에 따라 흰색/검정 중 자동 선택해 대비를 확보한다.
- 카카오톡 브랜드메시지 자체의 네이티브 버튼("바로 확인하기" 등)은 이 프로젝트의 스코프가 아니다 — 카카오 비즈니스 메시지 발송 도구에서 이 프로젝트가 만든 `/c/[slug]` URL을 링크로 연결해 사용한다.

## 인증

- `/admin` 이하 전체를 단일 공유 비밀번호로 보호한다. 로그인 폼에서 비밀번호를 검증하고, 성공 시 `SESSION_SECRET`으로 서명한 httpOnly 쿠키를 발급한다. 별도의 세션 저장소나 사용자 테이블은 두지 않는다(멀티유저 계정 없음).
- 미들웨어에서 `/admin` 경로 진입 시 쿠키 서명을 검증한다.
- `/c/[slug]`는 누구나 인증 없이 접근 가능하다. `status`가 draft/archived인 경우, 유효한 관리자 쿠키가 없으면 "아직 공개되지 않은 페이지입니다" 안내만 보여준다.

## 환경변수

- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` — 서버에서만 사용(클라이언트에 노출하지 않음). 사용자가 Supabase 프로젝트를 생성한 뒤 발급.
- `ADMIN_PASSWORD` — `/admin` 로그인 비밀번호.
- `SESSION_SECRET` — 로그인 쿠키 서명용 임의 문자열.

## 에러 핸들링

- 이미지 업로드 실패 시 인라인 에러 메시지, 재시도 가능.
- 리치 에디터에서 저장되는 `bodyHtml`은 서버에서 sanitize(허용 태그만 통과)한 뒤 DB에 저장해 저장형 XSS를 방지한다.
- 발행/임시저장 API 실패 시 폼 내용을 유지한 채 에러 메시지 표시(입력 내용 유실 방지).

## 테스트 계획

- 자동: `next build`, `tsc --noEmit`, `eslint` 통과 확인
- 수동 QA: 임시저장→발행 전체 흐름, draft/archived 상태 비공개 확인, 관리자 미리보기, 배너 이미지 업로드, 리치텍스트 서식 렌더링, 모바일/데스크톱 반응형, CTA 버튼 색상별 텍스트 대비
- 별도 유닛 테스트 프레임워크는 도입하지 않는다 (내부 소규모 도구 특성상 과함)

## 스코프 제외

- Supabase 프로젝트 실제 생성 및 키 발급 (사용자가 진행, 발급 후 전달받아 연동)
- 멀티유저 계정/권한 관리 (공유 비밀번호 1개)
- 조회수 등 방문 애널리틱스
- 드래그 앤 드롭 블록 정렬 (버튼 기반 순서변경으로 대체)
- 완전 삭제(하드 delete) 기능 (보관 처리까지만)
- Vercel 프로젝트 실제 연결/배포
- 카카오 비즈니스 메시지 발송 자체(버튼 스타일 포함) — 이 프로젝트는 그 버튼이 연결될 랜딩페이지만 만든다
- 다국어 지원 (한국어 전용)

## 미해결 사항

- Supabase 프로젝트 URL / Service Role Key 발급 필요 (사용자가 발급 예정)
- `ADMIN_PASSWORD`, `SESSION_SECRET` 값 결정 필요 (사용자가 정하거나, 구현 시 임의 생성 후 전달)
